# Verification & Acceptance

This document records **what was verified without a Windows toolchain**, **what cannot be verified
without one**, and the exact **acceptance runbook** to execute on the target terminal.

Kacher targets `net8.0-windows` + WPF. WPF cannot be compiled or rendered on Linux, so the source in
this repository has been reviewed and statically validated, not executed. Treat the CI job
(`.github/workflows/build.yml`) as the compile gate and the runbook below as the hardware gate.

---

## 1. Static checks performed

| # | Check | Method | Result |
|---|-------|--------|--------|
| 1 | Every `.xaml` is well-formed XML | `xml.etree.ElementTree` parse over `src/**/*.xaml` | pass |
| 2 | Every `x:Class` has a code-behind with a matching namespace + class | regex cross-reference (`Views/**`) | pass (only the two resource dictionaries `Themes/Colors.xaml`, `Themes/Styles.xaml` have no `x:Class`, by design) |
| 3 | Every `{Binding XCommand}` in a view is generated by a `[RelayCommand]` on that view's view model | per-view command map (77 generated commands) | pass |
| 4 | No `{StaticResource}`/`{DynamicResource}` key is undefined | collected all `x:Key`s (62) and resolved every reference | pass |
| 5 | Every DI constructor dependency of a registered type is resolvable | parsed `ConfigureServices`, matched ctor parameters against registered services | pass (`IDbContextFactory<T>`, `IServiceProvider`, `DbContextOptions<T>` resolve from the framework) |
| 6 | Balanced braces/parens/brackets in every `.cs` | character scanner ignoring strings/comments | pass |
| 7 | Compiled EF queries contain no `Include` (invalid in EF Core) | manual review of `ProductRepository` | pass |
| 8 | All persisted timestamps are UTC; local conversion only at the edges | review of `SaleService`, `Invoice`, `ReceiptDocumentBuilder`, `PdfReceiptService`, `ReportService` | pass |
| 9 | Money is `decimal` end-to-end (SQLite `TEXT` convention) | convention + review | pass |
| 10 | Seed data is internally consistent (EAN-13 check digits, unique keys) | recomputed mod-10 check digits; checked unique-index columns | pass |

### Known safe-by-design deviations

- **No EF migration files are checked in.** `DatabaseBootstrapper` calls `Migrate()` when migrations
  exist and transparently falls back to `EnsureCreated()` when they do not, logging a warning. This
  keeps a fresh clone runnable before the versioned baseline is generated. Generate it for production:
  `dotnet ef migrations add InitialCreate -p src/Kacher.Pos`.
- **CS8618 is a warning, not an error.** EF materialises entities and WPF sets some members
  reflectively; promoting this to an error would fail an unattended build for legitimate code.

## 2. Compile gate (CI)

`build.yml` runs on `windows-latest`:

```bash
dotnet restore Kacher.sln
dotnet build Kacher.sln --configuration Release --no-restore
```

RIDs are **not** pinned in the `.csproj`, so a plain build needs no RID graph. Publish separately:

```bash
dotnet publish src/Kacher.Pos -c Release -r win-x64 --self-contained false
```

## 3. Acceptance runbook (on the POS terminal)

Run in order; each step has a pass condition.

**Build & launch**

1. `dotnet build Kacher.sln -c Release` → 0 errors.
2. `dotnet run --project src/Kacher.Pos` → login window appears borderless, dark theme, PIN pad usable
   by touch.

**Database bootstrap**

3. Log in with `1234` (admin). → Shell loads; status bar shows cashier `Omar Khaled`.
4. Confirm `%LOCALAPPDATA%\Kacher\kacher.db` exists. → Schema + seed + `PRAGMA optimize` completed
   without a blocking dialog.

**Shift**

5. First run routes to **Shift** (no open shift). Enter an opening float of `500` → open.
6. Status bar flips to *Shift open*; nav to **Sales** becomes available.

**Sale + scanner**

7. Type or scan a product barcode with the field focused → line appears; quantity increments on rescan
   of the same barcode instead of adding a duplicate line.
8. With the barcode field **not** focused, scan again → item still lands in the cart and focus is not
   stolen (keyboard-wedge capture on `PreviewKeyDown`).
9. Adjust quantity with `+`/`−`, apply a line discount, delete a line → totals recompute instantly.

**Payment & printing**

10. `Process & Print` with **Cash** and an exact tender → dialog shows `Change 0.00`.
11. With **Card** → no drawer kick (verified by the drawer not opening).
12. Receipt prints: header, itemised table, tax bands, total, barcode/QR, footer; paper cuts cleanly.
13. Repeat with `PaperWidth = 58 mm` → columns reflow to 32 characters, no clipped lines.

**Drawer**

14. Cash sale with `OpenDrawerOnSale` → drawer pulses once, not twice.
15. Manual drawer button in **Hardware settings** → drawer opens; `ESC p 0 25 250` maps to
    `1B 70 00 19 FA`.

**Hardware settings**

16. Pick the printer from the detected queue list, **Test print** → page prints and the result banner
    reports success. With a wrong queue name, the banner warns *before* attempting the job.
17. **Probe printer** against a network printer on `:9100` → reports reachable/unreachable correctly.

**Close shift / reports**

18. Close the shift with a counted cash figure → variance computed; a note is required when the
    absolute variance exceeds `50 EGP`.
19. Closed-shift card appears with **Print Z-report** and **Export PDF**.
20. `Print Z-report` → ESC/POS summary prints; with the printer unplugged it falls back to a PDF and
    says so in a notification.
21. Reports → today/yesterday/range → totals match the shift summary; CSV and PDF exports open.

**Operator change**

22. Sign out → the process relaunches into the login window (no stale in-memory session).

## 4. Performance expectations

- All database, file and print work is `async`; no `.Result`/`.Wait()` on the UI thread.
- Print jobs are serialised on a single `SemaphoreSlim`, so a slow printer cannot stall rendering.
- Hardware health is polled every 20 s off the UI thread and only marshalled when the state changes.
- Catalogue binding is virtualised; the 56-product seed and multi-hundred product catalogues scroll
  without tearing on integrated graphics.
